# 主题用双份 CSS 令牌，终端配色跟随令牌

## 状态

accepted（2026-09-21）

## 决定

主题（深色 / 浅色 / 跟随系统）由**同一层 CSS 变量**承载：`:root` 是深色，`[data-theme="light"]` 覆写同名令牌。`color-scheme` 属于主题的一部分。xterm 的 `theme` **从这些令牌读**，不再硬编码。浅色主题下 **Acrylic 强制关闭**（面板令牌改为不透明），不给用户留下"浅底 + 桌面模糊 = 对比度不可控"的坑。

## Considered Options

- **JS 主题引擎**（运行时算色、注入 style）—— 否掉：CSS 变量已是本项目唯一主题机制，引入第二套只增加心智负担。
- **只做 UI 浅色、终端保持深色** —— 否掉：用户大部分时间盯着终端，终端不跟随等于浅色只做了一半。
- **做主题包（多套预设）** —— 超出本批范围。

## Consequences

- `runtime.ts` 里现有的 `theme: { background: "#080909", … }` 是**魔法值**，按本项目 D7 属于 bug，必须改为读令牌。往后任何一处硬编码颜色都违反本 ADR。
- 终端主题不是"设一次就不管"：会话 `attach` / `rebuild` / 实例重建时都要重新应用当前主题，否则切主题后老会话留旧配色。
- 「跟随系统」需要监听 OS 主题变更并即时反映，不能只在启动时读一次。
